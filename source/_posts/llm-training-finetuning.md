**一句话理解**：大模型一般先在海量文本上**预训练**学会“语言和知识”，再用指令数据做**监督微调（SFT）**学会“听指令”，最后用人类偏好做**对齐（RLHF / DPO 等）**学会“回答得让人满意”。LoRA、QLoRA 是让微调更省资源的方法。

<!-- more -->

## 通俗类比

- **预训练**：让一个人读完整个图书馆，他什么都懂一点，但只会“接着往下写”；
- **SFT**：给他看大量“问题—标准回答”示范，让他学会按要求答题；
- **RLHF / DPO**：老师比较他的两份回答，告诉他“这份更好”，他慢慢学会更符合人的偏好；
- **LoRA**：不重写整本教材，只在书页上贴“便利贴”做修订；
- **QLoRA**：教材先压缩成口袋版（4-bit），再贴便利贴，更省空间。

## 核心原理

### 1. 预训练（Pre-training）

GPT 一类模型的预训练目标是**预测下一个词**：给定前面的词，最大化下一个词的概率。数据是海量无标注文本，不需要人工标注，所以能做到很大规模。这一阶段决定了模型的基础知识和语言能力，**计算成本最高**。

预训练后的“基座模型”只会续写：你问它一个问题，它可能接着写出更多问题，而不是回答。

### 2. 监督微调（SFT）

用人工编写或筛选的“指令—回答”数据继续训练，目标仍然是预测下一个词，但只在高质量示范上学。效果是让模型学会**理解指令、按格式回答**。

### 3. RLHF：基于人类反馈的强化学习

以 OpenAI 的 InstructGPT 论文为代表，流程分三步：

| 步骤 | 做什么 |
| --- | --- |
| ① SFT | 用人工示范数据微调 |
| ② 训练奖励模型（RM） | 让模型对同一问题生成多个回答，人工排序；训练 RM 给“更好的回答”打更高分 |
| ③ 强化学习（PPO） | 用 RM 的打分当奖励优化模型，同时加 KL 惩罚，防止偏离 SFT 模型太远 |

奖励模型的成对损失（$y_w$ 是人更喜欢的回答，$y_l$ 是较差的回答，$\sigma$ 是 sigmoid）：

<div>
$$\mathcal{L}_{RM}=-\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\big(r_\theta(x,y_w)-r_\theta(x,y_l)\big)\right]$$
</div>

含义很直接：好回答的分数要比差回答高，差得越多损失越小。

InstructGPT 论文还提到：对齐后公开 NLP 任务上性能可能下降（论文称为“对齐税”），他们通过在 PPO 中混入预训练梯度（PPO-ptx）来缓解；而且模型**仍然会编造事实**。

### 4. DPO：直接偏好优化

RLHF 要训练奖励模型、再跑强化学习，流程复杂、不稳定。DPO（2023）证明可以**跳过显式奖励模型和强化学习**，直接用偏好数据做一个分类式的损失：

<div>
$$\mathcal{L}_{DPO}=-\mathbb{E}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{ref}(y_w\mid x)}-\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{ref}(y_l\mid x)}\right)\right]$$
</div>

- $\pi_\theta$：正在训练的模型；$\pi_{ref}$：参考模型（通常是 SFT 模型）；
- 直观理解：让模型相对参考模型，**提高好回答的概率、降低差回答的概率**；
- $\beta$ 控制偏离参考模型的程度，作用类似 RLHF 里的 KL 约束。

### 5. 全量微调 vs LoRA vs QLoRA

**全量微调**：更新模型全部参数。效果上限高，但显存、存储开销大，每个任务都要保存一份完整模型。

**LoRA（低秩适配）**：冻结原始权重 $W_0$，只训练两个小矩阵 $B$、$A$：

<div>
$$h=W_0x+\Delta Wx=W_0x+BAx,\quad B\in\mathbb{R}^{d\times r},\;A\in\mathbb{R}^{r\times k},\;r\ll\min(d,k)$$
</div>

- $A$ 用随机高斯初始化，$B$ 初始化为 0，所以训练一开始 $\Delta W=0$，模型行为不变；
- 更新量还会乘以缩放系数 $\alpha/r$；
- 训练完可以把 $BA$ **合并回** $W_0$，推理时**没有额外延迟**；
- 原论文主要把 LoRA 加在注意力的 $W_q$ 和 $W_v$ 上。

**QLoRA**：在 LoRA 基础上，把冻结的基座模型**量化成 4-bit** 存储，计算时再反量化为 BF16。论文的三个关键技术：

1. **NF4**（4-bit NormalFloat）数据类型；
2. **双重量化**：对量化常数再量化一次，进一步省内存；
3. **分页优化器**：缓解显存峰值。

论文的结论之一：要追平 16-bit 微调效果，需要把 LoRA 加到**所有线性层**上。

| 方法 | 训练参数量 | 显存需求 | 推理开销 | 适用 |
| --- | --- | --- | --- | --- |
| 全量微调 | 全部 | 最高 | 无额外 | 资源充足、改动大 |
| LoRA | 很少 | 低 | 合并后无额外 | 大多数定制场景 |
| QLoRA | 很少 | 更低 | 视部署方式 | 显存紧张 |

### 6. Prompt、RAG、微调怎么选

| 需求 | 优先方案 |
| --- | --- |
| 快速试验、任务简单 | Prompt（提示词工程） |
| 需要最新、私有、常变化的知识，要求可溯源 | RAG |
| 固定输出格式/风格、特定领域任务能力、降低长提示成本 | 微调 |
| 既要知识又要风格 | RAG + 微调结合 |

一般建议**从成本最低的 Prompt 开始**，不够再上 RAG，最后才考虑微调。这是业界常见思路，并非硬性规则。

## 常见误区

1. **“微调是给模型灌知识的最好办法”**：经常变化的事实性知识，用 RAG 更新更方便、可溯源；微调更擅长改变行为和格式。
2. **“LoRA 推理一定更慢”**：权重合并后，推理结构和原模型一样，没有额外延迟。
3. **“DPO 不需要偏好数据”**：错，DPO 省掉的是奖励模型和强化学习，**偏好对数据仍然需要**。
4. **“RLHF 之后模型就不胡说了”**：InstructGPT 论文自己就指出模型仍会编造事实。
5. **“QLoRA 用 4-bit 计算”**：QLoRA 是 4-bit **存储**基座权重，计算时反量化到 BF16。

## 面试高频问答（30 秒版）

**Q1：大模型训练分哪几个阶段？**
预训练（海量文本上预测下一个词，学语言和知识）→ SFT（指令示范数据，学会听指令）→ 偏好对齐（RLHF 或 DPO 等，让回答更符合人的偏好）。

**Q2：RLHF 的三个步骤？**
SFT；收集人工对多个回答的排序，训练奖励模型；用奖励模型做奖励、通过 PPO 优化策略，并加 KL 惩罚防止偏离 SFT 模型太远。

**Q3：DPO 和 RLHF 的区别？**
DPO 不训练显式奖励模型、也不跑强化学习，直接用偏好对构造一个分类式损失，让模型相对参考模型提高好回答概率、降低差回答概率。流程更简单、更稳定。

**Q4：LoRA 的原理？**
冻结原权重，把权重更新表示为两个低秩矩阵的乘积 $BA$，只训练它们。$B$ 初始为 0，所以初始不改变模型；训练后可合并回原权重，推理无额外延迟。

**Q5：QLoRA 比 LoRA 多做了什么？**
把冻结的基座模型量化为 4-bit（NF4）存储，再加双重量化和分页优化器，大幅降低显存，计算时反量化到 BF16，在其上训练 LoRA。

**Q6：什么时候选 RAG，什么时候选微调？**
知识经常变、需要私有数据和来源追溯，选 RAG；要改变输出格式、风格或提升某类任务能力，选微调。通常先试 Prompt，再 RAG，最后微调。

**Q7：RLHF 中为什么要加 KL 惩罚？**
防止模型为了刷高奖励模型分数而走偏（钻奖励模型的空子），让它和 SFT 模型保持接近，保证语言质量。

## 自测题

1. 为什么 LoRA 中把 $B$ 初始化为 0？
2. $d=k=4096$、$r=8$ 时，LoRA 对一个权重矩阵需要训练多少参数？全量需要多少？
3. DPO 公式中 $\pi_{ref}$ 起什么作用？
4. 奖励模型的损失为什么用两个回答的分数之**差**？
5. “公司产品手册每周更新，希望客服机器人回答准确”，应该优先选什么方案？

<details>
<summary>参考答案要点</summary>

1. 让训练开始时 $\Delta W=BA=0$，模型初始行为与原模型一致。
2. LoRA：$4096\times8+8\times4096=65536$；全量：$4096\times4096=16777216$。
3. 作为基准，衡量模型相对它的概率变化，并约束模型不要偏离太远。
4. 人类标注给的是“哪个更好”的相对比较，用差值建模偏好概率（Bradley-Terry 模型）。
5. RAG，知识每周变，更新知识库即可，还能给出来源。

</details>
