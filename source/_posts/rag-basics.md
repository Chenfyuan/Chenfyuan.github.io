**一句话理解**：RAG（Retrieval-Augmented Generation，检索增强生成）就是先从外部资料库里**检索**出和问题相关的内容，再把这些内容连同问题一起交给大模型，让它**参考资料生成**回答。

<!-- more -->

## 通俗类比

大模型像一个记性很好、但知识停在“毕业那天”的学生。直接闭卷考试，遇到没学过的内容，它可能会凭感觉编答案。

RAG 相当于把闭卷改成**开卷**：答题前先去资料室翻出最相关的几页，带着这些页再作答。资料室（知识库）可以随时更新，学生本身不用重新上学。

## 核心原理

### 1. RAG 从哪来

“RAG”这个名字来自 2020 年 Lewis 等人的论文 *Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks*。论文的做法：

- **检索器**：基于 DPR 的双编码器（问题和文档各用一个 BERT 编码成向量）；
- **生成器**：BART 这样的序列到序列模型；
- **知识库**：把维基百科切成 100 词左右的段落，建成向量索引，用最大内积搜索（MIPS）找最相关的段落；
- 提出了两种组合方式：**RAG-Sequence**（整个答案依赖同一批文档）和 **RAG-Token**（每个词可以依赖不同文档）。

论文还指出一个重要优点：**替换索引就能更新模型的知识**，不需要重新训练。

> 今天工程里说的“RAG”，泛指“检索 + 把结果塞进提示词 + 大模型生成”这一大类方案，不一定和原论文一样联合训练检索器。

### 2. 一条典型的 RAG 流水线

| 阶段 | 做什么 | 关键点 |
| --- | --- | --- |
| ① 文档解析 | 把 PDF、网页、表格等转成文本 | 解析质量直接决定上限 |
| ② 切分（Chunking） | 把长文档切成小块 | 块太大噪声多，块太小上下文断裂 |
| ③ 向量化（Embedding） | 用嵌入模型把每块变成向量 | 问题和文档要用配套的模型 |
| ④ 建索引 | 存入向量数据库或向量索引 | 常用近似最近邻（ANN）索引 |
| ⑤ 检索 | 把问题也向量化，找最相似的 Top-K 块 | 可结合关键词检索 |
| ⑥ 重排（Rerank，可选） | 用更精细的模型对候选重新排序 | 提高前几条的准确率 |
| ⑦ 生成 | 把检索结果和问题拼进提示词交给大模型 | 要求“依据资料回答，并标注来源” |

### 3. Embedding（向量化）

Embedding 模型把一段文本映射成一个固定长度的向量，**语义相近的文本，向量也相近**。比如“怎么重置密码”和“忘记密码怎么办”字面不同，但向量距离会比较近。这就是向量检索能做“语义匹配”的原因。

### 4. 相似度怎么算

最常见的是**余弦相似度**和**点积（内积）**：

<div>
$$\cos(\mathbf{a},\mathbf{b})=\frac{\mathbf{a}\cdot\mathbf{b}}{\lVert\mathbf{a}\rVert\,\lVert\mathbf{b}\rVert}$$
</div>

- 余弦只看方向不看长度，取值在 $[-1,1]$；
- 如果向量已经**归一化**（长度为 1），余弦相似度就等于点积，而且按欧氏距离排序也会得到相同顺序（因为 $\lVert\mathbf{a}-\mathbf{b}\rVert^2=2-2\,\mathbf{a}\cdot\mathbf{b}$）；
- 具体用哪种，要和嵌入模型训练时的设定一致。

### 5. 向量数据库与近似检索

数据量大时，逐条计算相似度太慢，所以通常用**近似最近邻（ANN）**索引，用一点点精度换大幅提速。RAG 原论文用的就是 FAISS 库，并用 HNSW 这类索引做近似搜索。“向量数据库”就是在这类索引之外，再提供存储、过滤、增删改等工程能力。

### 6. 切分策略（业界常见做法，做法不一）

- **固定长度切分**：按字数或 token 数切，通常让相邻块有一点重叠，避免一句话被切断；
- **按结构切分**：按标题、段落、句子切，保持语义完整；
- **语义切分**：根据内容变化点切分。

块大小、重叠多少**没有统一标准**，要结合文档类型和实际评测来调。

### 7. 混合检索与重排

- **关键词检索**（如 BM25）擅长精确匹配：型号、人名、专有名词；
- **向量检索**擅长语义匹配：同义改写、口语化提问；
- **混合检索**：两路结果合并，常见合并方式有加权分数、按排名融合等，**做法不一**；
- **重排**：先用快速方法召回较多候选，再用更精细的模型（常见是把“问题 + 文档”一起输入的交叉编码器）重新打分，只把前几条交给大模型。思路是“先粗筛，再精排”。

> RAG 原论文里也拿 BM25 做过对比：在某些以实体为中心的任务上 BM25 表现更好，说明关键词检索并没有过时。

### 8. 常见问题

| 问题 | 表现 | 常见应对思路 |
| --- | --- | --- |
| 检索不到 | 资料里有答案，但没召回 | 优化切分、混合检索、改写问题 |
| 检索到但排得靠后 | 相关内容没进 Top-K | 加重排、调 K |
| 噪声太多 | 无关块干扰回答 | 重排过滤、控制上下文长度 |
| 模型不用资料 | 无视检索内容，凭记忆答 | 提示词要求“仅依据资料”，并要求引用 |
| 资料冲突或过时 | 新旧版本混在一起 | 元数据过滤（时间、版本）、更新索引 |
| 多跳问题 | 答案分散在多篇文档里 | 多轮检索、问题拆解 |

### 9. 怎么评估 RAG

建议把**检索**和**生成**分开评估，这样才知道问题出在哪一环：

- **检索侧**：正确文档有没有出现在 Top-K 里（召回率 / 命中率），排在第几位（如 MRR 一类的排名指标）；
- **生成侧**：
  - **忠实度**：回答是否都有检索资料支撑，有没有编造；
  - **答案相关性**：是否回答了问题；
  - **正确性**：有标准答案时和标准答案比对。
- 生成侧常借助人工评审或“大模型当评委”（LLM-as-a-Judge），后者有偏差，需要抽样人工校验。不同评估框架对指标的命名和算法**不完全一致**。

## 常见误区

1. **“用了 RAG 就不会幻觉”**：错。检索错了、模型不用资料、资料本身有错，都会导致错误回答。RAG 只是**降低**幻觉的手段之一。
2. **“向量检索一定比关键词检索好”**：不一定。精确的型号、编号、专有名词，关键词检索往往更稳。
3. **“Top-K 越大越好”**：塞太多无关内容会稀释有效信息，还会增加成本和延迟。
4. **“RAG 能让模型学会新技能”**：RAG 提供的是**知识/资料**，不改变模型的能力和风格；要改变行为模式更适合微调。
5. **“块切得越小越精准”**：太小会丢掉上下文，模型拿到的是碎片。

## 面试高频问答（30 秒版）

**Q1：什么是 RAG？解决什么问题？**
先检索外部知识，再让大模型参考检索结果生成回答。主要解决模型知识过时、不了解私有数据、容易编造的问题，而且更新知识只需更新知识库，不用重新训练。

**Q2：说说 RAG 的完整流程。**
离线：文档解析、切分、向量化、建索引。在线：问题向量化、检索 Top-K、可选重排、把资料和问题拼进提示词、模型生成并标注来源。

**Q3：为什么要做混合检索？**
向量检索擅长语义匹配，但对精确的编号、专有名词不敏感；BM25 这类关键词检索正好相反。两者结合能互补，提高召回。

**Q4：重排（Rerank）有什么用？**
第一轮检索追求快和召回，排序不够精细。重排用更精细的模型（常见是交叉编码器）同时看问题和文档，重新打分，让真正相关的内容排到前面，再交给大模型。

**Q5：chunk 大小怎么定？**
没有统一标准。太大噪声多、占上下文，太小语义不完整。一般按文档结构切并保留少量重叠，最后用评测集对比不同设置来定。

**Q6：RAG 效果不好怎么排查？**
先分环节：看正确文档有没有被检索到。没检索到就查解析、切分、嵌入模型和检索策略；检索到了但答错，就查重排、提示词和上下文长度，看模型是否真的用了资料。

**Q7：RAG 和微调怎么选？**
需要最新的、私有的、经常变化的知识，并且要可追溯来源，优先 RAG；需要改变模型的输出格式、风格或特定任务能力，考虑微调。两者也可以结合使用。

**Q8：余弦相似度和点积有什么关系？**
余弦相似度是点积除以两个向量长度的乘积。向量归一化后，两者完全相等。

## 自测题

1. 用户问“型号 XK-2031 的保修期多久”，纯向量检索可能出什么问题？你会怎么改？
2. 为什么建议把检索和生成分开评估？
3. 向量已归一化时，按余弦相似度排序和按欧氏距离排序结果一样吗？为什么？
4. RAG 原论文中 RAG-Sequence 与 RAG-Token 的区别是什么？
5. 列举三个可能导致“资料里有答案、模型却答错”的原因。

<details>
<summary>参考答案要点</summary>

1. 编号语义信息弱，可能召回别的型号；加入关键词检索（混合检索）或元数据过滤。
2. 能定位是检索没找到，还是找到了没用好。
3. 一样。$\lVert a-b\rVert^2=2-2a\cdot b$，距离越小点积越大。
4. RAG-Sequence 整个输出用同一篇文档；RAG-Token 每生成一个词都可以依赖不同文档。
5. 没检索到或排名靠后；上下文噪声太多；模型没有遵循资料；资料本身有冲突或过时。

</details>
